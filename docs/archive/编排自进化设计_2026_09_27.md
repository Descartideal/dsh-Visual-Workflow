# 第一部分 方案本体

## 一、开发目标

本阶段基于当前元编排架构，建立一个可以实际运行的最小闭环。

### 1.1 经验闭环

```text
历史经验
    ↓
wf_org_catalog
    ↓
父代理获得：
  1. Experience：过去编排中值得注意的经验（新增）
  2. Asset：可以参考的配置（角色、工作流，当前已有，但需要改造为读取资产，而非模板）
  3. 其他：规则、工具组合、模型等（不变）
    ↓
父代理生成本次任务的组织结构
    ↓
Workflow 执行
    ↓
执行结束
    ↓
检测到工作流运行 结束/失败，自动注入复盘提示词
    ↓
父代理复盘
    ↓
生成 Experience Candidate（渲染多项选择卡片）
    ↓
用户确认 / 修改 / 丢弃
    ↓
Experience DB（经验落盘数据库）
    ↓
下一次 Catalog 召回
```

### 1.2 资产生命周期

```text
用户编辑/创建模板（工作流模板、角色模板）
    ↓
用户确认“可复用”（属性栏渲染“入库”按钮）
    ↓
Active Asset（落盘为资产）
    ↓
Catalog 可召回（当前召回的是工作区模板，需要改造为召回资产）
    ↓
后续编辑
    ↓
新的 Version
    ↓
召回复用
```

资产历史版本全部保留，可以随时回滚。

### 1.3 核心原则

> **先让“经验闭环”和“资产生命周期闭环”真正跑起来。**

## 二、V1 持久化数据存储（SQLite）

### 2.1 Experience DB

职责：

> 保存执行复盘后形成、经过用户确认的可复用经验。

Experience 不是 Workflow，也不是运行日志。

它回答的是：

> “过去发生了什么？未来遇到类似任务时需要注意什么？”

#### Experience V1 语义结构

```text
Retrieval
├── task_type
└── task_context

Experience Content（经验的完整内容）
```

#### Retrieval 字段（用于向量检索）

`task_type`

用于粗粒度任务类型。例如：

```text
软件开发
```

`task_context`

用于语义检索的自然语言上下文。例如：

```text
面向消费者的移动端外卖平台 App 开发，包含用户端、商家端与订单流程。
```

它不是严格分类标签，而是未来向量/语义检索提供的检索锚点。

目标：

```text
编排任务
    ↓
父代理传入检索关键词
    ↓
Catalog 工具通过向量检索召回经验
    ↓
Top-K Experience
    ↓
父代理判断是否真正适用
```

向量检索只负责寻找语义相似候选。

**最终是否适用，由父代理进行语义判断。**

> V1 暂未启用向量检索通道，相关字段为预留字段；召回仍采用层级召回。

### 2.2 最终 DDL（已按实施定案修正）

> 以下 DDL 融合实施定案第三节修正点，作为 V1 最终实施口径。  
> 时间统一为 epoch 毫秒（INTEGER）。  
> 初始化时执行 `PRAGMA foreign_keys = ON`；`journal_mode = WAL` 失败时降级，不抛错。

```sql
PRAGMA foreign_keys = ON;
-- journal_mode = WAL 初始化时尝试；失败降级不抛错

-- =========================================================
-- 1. experiences — 经验表
-- =========================================================
CREATE TABLE IF NOT EXISTS experiences (
    id TEXT PRIMARY KEY, -- 经验唯一 ID，前缀 ex-*，例如 ex-xxx
    source_run_id TEXT, -- 产生该经验的那次工作流运行 ID，用于回溯；可为空
    reflection_prompt_version TEXT NOT NULL DEFAULT '1', -- 生成该经验时使用的复盘 Prompt 版本号；当前固定 '1'
    task_type TEXT NOT NULL, -- 任务类型（粗粒度），例如：软件开发
    task_context TEXT NOT NULL, -- 任务语义上下文（自然语言），用于检索与适用性判断
    insight TEXT NOT NULL, -- 从本次运行复盘提炼出的可复用经验
    evidence TEXT, -- 支撑该经验的关键事实/证据，只保留关键事实；可为空
    review_feedback TEXT, -- 人工审核意见、修改意见或纠正内容；没有则留空
    reviewed_at INTEGER, -- 人工审核时间；未审核为 NULL
    created_at INTEGER NOT NULL, -- 经验创建时间
    updated_at INTEGER NOT NULL -- 经验最后更新时间
);

CREATE INDEX IF NOT EXISTS idx_experiences_task_type ON experiences(task_type);
CREATE INDEX IF NOT EXISTS idx_experiences_source_run_id ON experiences(source_run_id);
CREATE INDEX IF NOT EXISTS idx_experiences_created_at ON experiences(created_at);

-- =========================================================
-- 2. role_asset_history — 角色资产历史表
-- =========================================================
CREATE TABLE IF NOT EXISTS role_asset_history (
    id TEXT PRIMARY KEY, -- 该版本行的全局唯一 ID，格式 <asset_id>@<version_id>，例如 role-xxx@1
    version_id INTEGER NOT NULL, -- 角色资产版本号（整数，从 1 自增；前端显示为 v1、v2）
    asset_id TEXT NOT NULL, -- 角色资产逻辑 ID，前缀 role-*，同一角色跨版本保持不变
    kind TEXT NOT NULL CHECK (kind IN ('parent', 'agent')), -- 角色类型/用途，与 RoleNode.kind 同域
    name TEXT NOT NULL, -- 角色名称
    system_prompt TEXT NOT NULL, -- 角色的系统提示词
    provider TEXT NOT NULL, -- 模型提供商
    model TEXT NOT NULL, -- 使用的模型名
    reasoning TEXT NOT NULL, -- 推理配置/思考强度
    preset_id TEXT NOT NULL, -- 关联的预设 ID
    retry_limit INTEGER CHECK (retry_limit >= 0), -- 重试次数限制，必须为非负整数
    react_limit INTEGER CHECK (react_limit IS NULL OR react_limit >= 0), -- React/循环执行次数限制；可为空，非空时必须非负
    input_schema TEXT CHECK (input_schema IS NULL OR json_valid(input_schema)), -- 角色输入结构定义（JSON 字符串）；可为空
    output_schema TEXT CHECK (output_schema IS NULL OR json_valid(output_schema)), -- 角色输出结构定义（JSON 字符串）；可为空
    system_prompt_source TEXT, -- 角色 Prompt 来源文件名；可为空
    inject_system_prompt INTEGER CHECK (inject_system_prompt IN (0,1)), -- 是否注入官方系统提示词：0=否，1=是
    inject_tool_sections INTEGER CHECK (inject_tool_sections IN (0,1)), -- 是否注入官方工具相关提示词：0=否，1=是
    prompt_file_path TEXT, -- 外部 Prompt 文件路径（如果存在）；可为空
    retrieval_context TEXT, -- 该角色用于检索的上下文描述；预留，暂时无用

    role_asset_type TEXT NOT NULL
        CHECK (role_asset_type IN ('standalone', 'inline', 'shared')),
        -- standalone：独立角色资产
        -- inline：被工作流引用的内联角色资产
        -- shared：多次引用的共享角色资产

    reference_workflow_ids TEXT NOT NULL DEFAULT '[]'
        CHECK (json_valid(reference_workflow_ids)),
        -- 累计引用过该角色版本的工作流 workflow_asset_history.id 数组（JSON 字符串）
        -- 单调递增，新版本创建时重置为 []

    reference_status TEXT NOT NULL DEFAULT 'unused'
        CHECK (reference_status IN ('unused', 'used')),
        -- 引用统计状态；新版本为 unused；一旦 used 不回退

    source TEXT NOT NULL CHECK (source IN ('human','agent')), -- 该版本来源：human=人类创建/修改；agent=代理生成
    source_template_id TEXT, -- 来源模版 ID；用于模版 ↔ 资产绑定
    source_fingerprint TEXT, -- 来源模版内容指纹；用于入库按钮锁定/幂等短路
    created_at INTEGER NOT NULL, -- 该版本创建时间
    updated_at INTEGER NOT NULL, -- 该版本最后更新时间；reference_* 等统计缓存变化时更新

    UNIQUE(asset_id, version_id) -- 保证同一角色的版本号唯一，同时作为 role_asset_active 复合外键的引用目标
);

CREATE INDEX IF NOT EXISTS idx_role_history_asset_id ON role_asset_history(asset_id);
CREATE INDEX IF NOT EXISTS idx_role_history_status ON role_asset_history(reference_status);
CREATE INDEX IF NOT EXISTS idx_role_history_source_template ON role_asset_history(source_template_id);

-- =========================================================
-- 3. workflow_asset_history — 工作流资产历史表
-- =========================================================
CREATE TABLE IF NOT EXISTS workflow_asset_history (
    id TEXT PRIMARY KEY, -- 该版本行的全局唯一 ID，格式 <asset_id>@<version_id>，例如 flow-xxx@1
    version_id INTEGER NOT NULL, -- 工作流资产版本号（整数，从 1 自增；前端显示为 v1、v2）
    asset_id TEXT NOT NULL, -- 工作流资产逻辑 ID，前缀 flow-*，同一工作流跨版本保持不变
    mode TEXT NOT NULL CHECK (mode IN ('mode1', 'mode2')), -- Workflow 模式；V1 固定枚举为 mode1 / mode2

    name TEXT NOT NULL, -- 工作流名称
    description TEXT NOT NULL, -- 工作流描述

    nodes_json TEXT NOT NULL CHECK (json_valid(nodes_json)),
        -- 工作流节点骨架 JSON；用于重建角色节点位置/groupId/节点 id 等

    role_version_ids TEXT NOT NULL DEFAULT '[]'
        CHECK (json_valid(role_version_ids)),
        -- 该工作流版本引用的角色版本映射数组（JSON 字符串）
        -- 格式：[{"nodeId":"...","roleVersionId":"role-xxx@1"}]
        -- roleVersionId 存的是 role_asset_history.id，用于固定回放时的角色版本

    other_nodes_json TEXT NOT NULL CHECK (json_valid(other_nodes_json)), -- 工作流除角色节点外的其他节点 JSON
    lines_json TEXT NOT NULL CHECK (json_valid(lines_json)), -- 工作流连线 Line[] 的 JSON
    meta_json TEXT CHECK (meta_json IS NULL OR json_valid(meta_json)), -- OrgMeta 等组织编排元数据的 JSON；可为空
    retrieval_context TEXT, -- 该工作流用于检索的上下文描述；预留，暂时无用

    source TEXT NOT NULL CHECK (source IN ('human','agent')), -- 该版本来源
    source_run_id TEXT, -- 如果由某次运行产生，则记录运行 ID；UI 晋升路径写 NULL，字段留给复盘链路补写
    source_template_id TEXT, -- 来源模版 ID；用于模版 ↔ 资产绑定
    source_fingerprint TEXT, -- 来源模版内容指纹；用于入库按钮锁定/幂等短路
    created_at INTEGER NOT NULL, -- 该版本创建时间

    UNIQUE(asset_id, version_id) -- 保证同一工作流的版本号唯一
);

CREATE INDEX IF NOT EXISTS idx_workflow_history_asset_id ON workflow_asset_history(asset_id);
CREATE INDEX IF NOT EXISTS idx_workflow_history_source_template ON workflow_asset_history(source_template_id);

-- =========================================================
-- 4. role_asset_active — 当前有效角色资产索引表
-- =========================================================
CREATE TABLE IF NOT EXISTS role_asset_active (
    asset_id TEXT PRIMARY KEY, -- 角色资产逻辑 ID，前缀 role-*；同一角色只有一条 Active 记录
    version_id INTEGER NOT NULL, -- 当前正在生效的正式版本号；默认最新版，可回滚修改
    name TEXT NOT NULL, -- 当前生效版本的角色名称（冗余，用于检索展示）
    retrieval_context TEXT NOT NULL, -- 当前生效版本的检索上下文文本：id + name + kind + system_prompt 前 60 字摘要
    embedding BLOB, -- 该角色的向量表示；未生成向量时为空；V1 预留
    embedding_dimension INTEGER, -- 向量维度；可为空；V1 预留
    embedding_source TEXT, -- 向量来源，例如 local、remote；可为空；V1 预留
    embedding_model TEXT, -- 生成该向量所用的 Embedding 模型名；可为空；V1 预留
    source_template_id TEXT, -- Active 版本来源模版 ID 投影；回滚时随之刷新
    source_fingerprint TEXT, -- Active 版本来源指纹投影；回滚时随之刷新
    updated_at INTEGER NOT NULL, -- 当前索引最后更新时间

    FOREIGN KEY (asset_id, version_id)
        REFERENCES role_asset_history(asset_id, version_id)
);

CREATE INDEX IF NOT EXISTS idx_role_active_version ON role_asset_active(asset_id, version_id);

-- =========================================================
-- 5. workflow_asset_active — 当前有效工作流资产索引表
-- =========================================================
CREATE TABLE IF NOT EXISTS workflow_asset_active (
    asset_id TEXT PRIMARY KEY, -- 工作流资产逻辑 ID，前缀 flow-*；同一工作流只有一条 Active 记录
    version_id INTEGER NOT NULL, -- 当前正在生效的正式版本号；默认最新版，可回滚修改
    name TEXT NOT NULL, -- 当前生效版本的工作流名称（冗余，用于检索展示）
    retrieval_context TEXT NOT NULL, -- 当前生效版本的语义检索上下文文本：id + name + description
    embedding BLOB, -- 该工作流的向量表示；未生成向量时为空；V1 预留
    embedding_dimension INTEGER, -- 向量维度；可为空；V1 预留
    embedding_source TEXT, -- 向量来源，例如 local、remote；可为空；V1 预留
    embedding_model TEXT, -- 生成该向量所用的 Embedding 模型名；可为空；V1 预留
    source_template_id TEXT, -- Active 版本来源模版 ID 投影；回滚时随之刷新
    source_fingerprint TEXT, -- Active 版本来源指纹投影；回滚时随之刷新
    updated_at INTEGER NOT NULL, -- 当前索引最后更新时间

    FOREIGN KEY (asset_id, version_id)
        REFERENCES workflow_asset_history(asset_id, version_id)
);

CREATE INDEX IF NOT EXISTS idx_workflow_active_version ON workflow_asset_active(asset_id, version_id);
```

### 2.3 写代码时要注意的语义

1. **事实源 vs 统计缓存**
   - 事实源：`workflow_asset_history.role_version_ids`
   - 统计缓存：`role_asset_history.reference_status` / `reference_workflow_ids`
   - 写入新工作流版本时，必须在同一事务里同步更新被引用角色版本的统计字段。

2. **引用统计规则**
   - 按“角色版本”累计，不跨版本。
   - 新版本创建时，`reference_status = 'unused'`，`reference_workflow_ids = '[]'`。
   - 一旦 `used` 不回退。

3. **回滚语义**
   - 回滚 = 修改 `*_asset_active.version_id` 指向历史表里的某个版本。
   - 历史表内容不变。

4. **版本号**
   - `version_id` 是整数，前端显示时加 `v`。
   - 新版本号 = 该 `asset_id` 下 `max(version_id) + 1`。

5. **JSON 字段**
   - 所有 `*_json`、`*_schema`、`role_version_ids`、`reference_workflow_ids` 都必须是合法 JSON 字符串。
   - 写入前用应用层序列化，不要手拼字符串。

6. **ID 命名**
   - 经验：`ex-*`
   - 角色资产：`role-*`
   - 工作流资产：`flow-*`
   - 版本行 ID：`<asset_id>@<version_id>`

## 三、复盘

一次 Workflow 执行完成后的正确流程：

```text
Workflow Run
    ↓
父代理已有完整上下文
    +
Runtime 提供机器事实
    ↓
反思回顾
    ↓
0～N 个 Experience
    ↓
渲染多选提问卡片
    ↓
用户可多选值得入库的经验
    ↓
入库 Experience DB
```

### Runtime 提供机器事实

Runtime 负责提供确定性事实，例如：

- token 使用（包含所有子代理）
- retry
- timeout
- 子代理总数量
- 上下文健康度（包含子代理）
- 执行时间
- 其他通过上下文获取不到但对复盘很有用的参数和运行事实

> 实施定案 V1 冻结：机器事实只要三项：run 状态、总耗时、节点总数。  
> token 用量与上下文健康度本阶段不采集，字段预留。

## 四、复盘 Prompt 的职责

复盘 Prompt 不应该要求：

> “总结本次任务。”

而应该要求：

> “从本次组织执行过程中识别未来可能具有参考价值的组织经验。”

建议复盘逻辑：

```text
1. 回顾任务上下文
2. 回顾初始组织形态
3. 回顾组织执行过程
4. 找出重要偏差
5. 分析 Action → Outcome
6. 生成 Experience
7. 检查是否过度泛化
8. 如果没有足够价值，可以返回 0 条
```

必须区分：

```text
Fact
Inference
```

例如：

```text
Fact：
子代理发生 context limit。

Inference：
因此本次采用 rotation/handoff 是合理的。

Experience：
当任务阶段较长且子代理接近 context limit 时，
可以采用结构化 handoff/rotation 保持阶段信息连续性。
```

不能简单因为：

```text
采用 A
+
任务最终成功
=
A 是好策略
```

而生成经验。

## 五、Experience

Experience 是未来组织生成时的参考知识单元，不是日志压缩，也不是完整 Run Summary。

总量控制在约 500 个中文字符以内，结构化表述。

其他规则：

- 允许 0 条
- 不强制生成经验
- 不复制长日志
- Insight 尽量是单句
- Evidence 只保留关键事实
- 语义重复应合并
- 不确定时宁可不产生

---

## 六、Asset 的职责

Experience 和 Asset 必须保持明确分工。

```text
Experience
= “这类任务过去发生过什么、以后需要注意什么”

Asset
= “这类任务可以参考什么组织配置”
```

例如：

Experience：

```text
长时间开发任务中，子代理接近上下文限制时，
提前进行结构化交接可以减少阶段信息丢失。
```

Asset：

```text
需求分析
    ↓
架构设计
    ↓
前端开发 ─┐
          ├→ 集成测试
后端开发 ─┘
```

因此 Catalog 每次召回的两个核心部分就是：

```text
Experience
    ↓
告诉父代理：
“这次编排需要注意什么”

Asset
    ↓
告诉父代理：
“有哪些组织配置可以参考”
```

这构成一次新编排的基础条件。

## 七、资产状态

V1 只需要两个生命周期状态：

```text
Active
Retired
```

### Active

当前正式可复用资产。

特点：

- 可以进入 Catalog
- 可以被父代理召回
- 是当前有效版本（默认最新版，可更改）

### Retired

历史版本保留但不再正常召回。

> 实施定案 V1：删除 = 退役。Active 移除、历史保留可查。`shared` 角色资产删除时文案提示级联影响。

---

## 八、Active Asset DB

Active Asset DB 是：

> **Catalog 的当前可复用资产检索源。**

它不是完整资产数据库。

Catalog 从 Active Asset DB 获取资产索引并通过 id 召回相应资产的完整内容。

这样可以确保历史版本不会污染正常召回。

---

## 九、Asset History DB

Asset History DB 保存：

> **所有正式资产版本，包括当前 Active 版本。**

例如：

```text
Asset A
├── v1
├── v2
└── v3 ← 当前 Active
```

Active Asset DB：

```text
Asset A → v3
```

如果回滚：

```text
用户选择 v1
    ↓
Asset History DB
    ↓
Asset A v1
    ↓
重新设为 Active
    ↓
Active Asset DB
    ↓
Asset A → v1
```

历史数据本身不被修改。

---

## 十、Asset ID 与 Version ID 必须分离

不要把版本直接理解为不同 Asset。

建议：

```text
asset_id
version_id
```

例如：

```text
asset_id   = frontend_development
version_id = v3
```

历史库：

```text
frontend_development
├── v1
├── v2
└── v3
```

Active DB：

```text
frontend_development → v3
```

因此：

> 回滚不是“复制旧资产”，而是“改变当前有效版本指向”。

具体数据库实现由现有项目技术栈决定，但必须保证这个语义。

## 十三、资产去重机制

由于从资产转化为内联节点时存在深拷贝解耦机制，导致工作流资产储存时，会出现资产中重复一模一样的角色，因此增加去重机制。

每个角色资产或工作流资产在储存之前，对已有的所有资产进行对比。当新储存的角色字段 `system_prompt` 与资产中已存在版本角色相同字段一模一样时，将已存在角色的 `role_asset_type` 字段从 `standalone` 或 `inline` 更新为 `shared`，然后在 `reference_workflow_ids` 字段中登记引用这个角色的工作流 id。

场景：

- 当工作流资产保存时，其中的内联节点角色也会同步保存为角色资产。因此，当该角色资产与原本已登记过的角色资产重复时就需要去重。
- 同理，当从模板晋升成为资产时，如果该资产与已登记的工作流资产所产生的内联节点角色资产重复时，也会将角色资产类型变更为 `shared`。

最简单的区分：

> 当一个资产被修改时，如果会触发多个资产的级联修改，它就必须是 `shared` 的。  
> 而 `standalone` 和 `inline` 只是来源不同，但它们修改时都不会触发级联效应。

角色资产类型说明：

- `standalone`：独立角色资产。即直接由角色模版晋升而来的资产，且该资产未被任何工作流资产登记引用过。
- `inline`：工作流的内联角色资产。即直接由工作流模版晋升而带来的内联角色资产，且该资产未被任何其他工作流资产登记引用过，也没有与 `standalone` 重复。
- `shared`：多次引用的共享角色资产，涉及级联修改。被多个工作流资产登记引用过，或 `standalone` 与 `inline` 产生重复。

入库去重规则：

- 资产登记入库时，`standalone` 与 `standalone` 发生重复：直接取消当次入库。
- `inline` 与 `inline` 重复：类型变为 `shared`。
- `standalone` 与 `inline` 重复：类型变为 `shared`。
- 工作流资产本身重复登记：取消当次入库，直接在 UI 层面解决。

## 二、用户裁决（V1 冻结）

### 2.1 架构与存储

1. **持久化**：`node:sqlite` 单库，落盘 `<dataDir>/assets.db`，新模块 `src/host/assets/`；storage 层（JSON）保持不动，两套事实源互不越界。
2. **模版 ↔ 资产绑定**：记在资产历史行（`source_template_id` + `source_fingerprint`），Active 索引冗余保存当前 Active 版本的投影；同一模版再次入库 = 同一 `asset_id` 的新版本。
3. **节点来源标记**：`RoleNode.data.sourceAssetId?`（仅「从资产拖入画布」时写入；不参与执行，不进 `wf_graph_patch` 字段面）。

### 2.2 去重与版本

4. **去重匹配键** = `kind + system_prompt` 全等（父代理角色与子代理角色不互相去重）。
5. 角色模版入库时与已有 `standalone` 资产重复 → **取消当次入库**（`ERR_ASSET_DUPLICATE`）；与 `inline`/`shared` 重复 → 合并到已有资产并把类型置 `shared`。
6. 内联角色内容与**源角色资产**当前版本不一致（改动过）→ 登记为该**源资产的新版本**；一致 → 只登记引用（触发去重）。
7. 工作流资产重复登记在 UI 层拦截（入库按钮按内容指纹锁定）；后端对「同模版同指纹」做幂等短路（不新增版本）。
8. 新版本号 = 该 `asset_id` 下 `max(version_id) + 1`；**回滚不新增版本**，只改 Active 指针。
9. 引用统计按「角色版本」累计、单调递增；新版本创建时重置为 `[]` / `unused`；一旦 `used` 不回退；被 ≥2 个工作流版本引用 → `shared`。

### 2.3 经验闭环

10. **复盘触发**：`completed` / `failed` / `stopped` 三种终态都注入；`paused`、`interrupted` 不注入；同一 runId 只注入一次（幂等）。
11. **机器事实只要三项**：run 状态、总耗时、节点总数（token 用量与上下文健康度本阶段不采集，字段预留）。
12. **经验入库交互**：新增 `wf_experience`（父代理可见、子代理永久隐藏），内部借官方 `userQuestions` 渲染多选卡片，用户选定后**同一次调用原子入库**；未确认绝不入库；允许 0 条。
13. `source` 恒为 `'human'`：V1 只允许人类点击入库（`agent` 取值预留）。
14. **召回面**：`wf_org_catalog` **彻底移除模版索引**，只召回资产 `flow-*` / `role-*` + 经验 `ex-*`；经验与资产同为层级召回（第一层 `id + task_context`，第二层 `insight + evidence`）；详情只召回 Active 版本（不支持 `@vN`）。

### 2.4 UI 交互

15. 底部「模版 / 资产」切换**同时**切左侧库来源与画布文档类型；资产态「运行」与模版态一致（先转实例再运行）。
16. 资产态：工作流 tab 直接列工作流资产（无实例/模版分区）；角色 tab 直接列角色资产（无父/子分区）；数据/其他 tab 空态提示。
17. 搜索栏常驻两态、共用关键词，过滤当前 tab 全部分区（含模版态实例列表），匹配名称 + 描述 / 角色提示词。
18. 入库按钮按**内容指纹**锁定（入库时指纹 = 模版当前指纹即锁定；模版再被修改即解锁）；入库成功后只 toast，不切态。
19. 属性栏底部按钮按图 3 两态分录：模版态 = 保存（覆盖草稿）/ 删除 / 入库；资产态 = 保存（登记新版本）/ 删除（退役，二次确认）/ 回滚（版本上拉列表，免确认）。入库在资产态隐藏、回滚在模版态隐藏。
20. 角色资产在资产态点击 = 属性栏编辑（可保存新版本 / 回滚 / 退役）。
21. 删除 = 退役（Active 移除、历史保留可查）；`shared` 角色资产删除时文案提示级联影响。
22. 资产只能由模版晋升，无「新建资产」入口。
23. V1 不做经验管理界面（经验只经 `wf_org_catalog` 召回 + `wf_experience` 入库）。

## 三、表结构（相对需求原文的修正）

修正点如下，实施以本文修正后的 DDL 为准。

| # | 修正 | 原因 |
|---|---|---|
| 1 | `role_asset_history` 补 `reference_status` | 需求语义段与 `idx_role_history_status` 引用了它，原 DDL 漏列 |
| 2 | `role_asset_history` 补 `updated_at` | `role_asset_type` / `reference_*` 是可变统计缓存，需要变更时间 |
| 3 | `workflow_asset_history` 补 `nodes_json` | 角色版本行不含 `position` / `groupId` / 节点 id，原表无法重建骨架 |

| 3 | 经验无管理界面 | 按裁决 V1 不做；经验只经 `wf_org_catalog` 召回 + `wf_experience` 入库 |
| 4 | 模式二（服务）工作流模版同样可入库 | 资产表允许 `mode1/mode2`；资产态运行走「先转实例/服务再运行」 |
| 5 | 同图内内容全等的角色节点会把角色资产直接升 `shared` | 用户去重规则「重复即升 shared」的直接推论，已测试锁定 |
| 6 | `workflow_asset_history.source_run_id` 在 UI 晋升路径为 NULL | 该入口没有 run 上下文；字段留给复盘链路补写 |
| 7 | `listAssets` 的 `currentTemplateFingerprint` 是每资产一次模版读 | V1 资产量小可接受；后续可在单次请求内按 templateId 去重 |
| 8 | `scheduleIdleWatchdog` 在 Windows 高并发全量跑下偶发超时 | 单跑 5/5 通过（378ms）；属测试负载敏感，非功能缺陷 |

## 八、最终实施口径摘要

1. **事实源分离**：JSON storage 管模版/草稿；`assets.db` 管资产、版本、Active、引用统计、经验。
2. **模版晋升资产**：入库按钮触发；先保存后入库；按内容指纹锁定；重复入库由 UI 与后端幂等共同拦截。
3. **资产版本模型**：`asset_id` 逻辑不变，`version_id` 递增；回滚只改 Active 指针，不新增版本，不改历史。
4. **Catalog 召回**：不再召回模版，只召回 `flow-*` / `role-*` / `ex-*`；层级召回；详情只取 Active。
5. **经验闭环**：终态 `completed/failed/stopped` 注入复盘；`wf_experience` 多选确认后原子入库；允许 0 条。
6. **V1 不做**：向量检索、经验管理界面、新建资产入口、token/上下文健康度采集。
7. **验收基准**：以实施定案为准，以 `tests/integration/asset-lifecycle.test.ts` 锁定链路为最小集成验证。
